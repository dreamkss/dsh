# 导入方法

## 一、安装

preset 就是一个目录，放在 DSH 的**用户 preset 根**下即可被识别。

```powershell
$dshHome = if ($env:DSH_HOME) { $env:DSH_HOME } else { "$env:USERPROFILE\.dsh" }
$dest = Join-Path $dshHome '.agent-presets\verified'

New-Item -ItemType Directory -Path $dest -Force | Out-Null
Copy-Item .\preset\* $dest -Force
```

结果：

```
<dshHome>/.agent-presets/verified/
├── agent.cordis.yml
└── preset.yml
```

**目录名即 preset 的 `id`。** 上例的 `id` 是 `verified`，显示名由 `preset.yml` 的
`name` 决定（本 preset 为「核实模式」）。

### 为什么是这个位置

DSH 的 preset 来自两处（引自 `@deepseek-ai/dsh-agent-presets` 的 README）：

> The presets you can choose from come from two places: the presets shipped inside
> this package under `presets/`, and your own presets under `<dshHome>/.agent-presets`.

用户根由 `includeUserRoot` 控制，默认为 `true`，且排在所有已配置根之后。

## 二、生效

**新建一个会话**，在 preset 选择器里选「核实模式」。

三条必须知道的机制（同样引自该 README）：

1. **只有空会话能切换 preset。**
   > only an empty session may switch presets.

   已经产生过内容的会话不能换 —— 换掉 composition 会让历史里已记录的 tool call
   在新组合下无法复现。

2. **组合在 agent 发布前安装一次，运行期不再重读。**
   > a composition is installed once, before the agent is published and therefore
   > before its first request, and is never re-read while the agent runs.

   所以**改完文件不会影响正在运行的会话**，必须开新会话。

3. **每个会话可有不同 preset，状态互相隔离。**
   > One process can run sessions with different presets while keeping their state
   > separate.

## 三、验证安装是否成功

### 3.1 本地文件校验（不需要启动 DSH）

```powershell
node verify-preset.cjs
```

### 3.2 挂载校验

preset 的 composition 由 `agentPresets.standingKeyFor(id)` 做真实挂载校验：它组合
preset 的插件子树（与会话启动相同，只是不含 agent），**只有成功才正常返回**。失败会
以四类之一拒绝：

- 某行的包无法解析
- 某行 config 非法
- 有行始终未激活（在等一个没人提供的服务）
- 服务泄漏到进程级 realm

本 preset 的这一项已通过（见下节）。

### 3.3 真实会话确认

挂载校验**不等于**确认产出。最终一步是新建会话选「核实模式」，确认工具列表与预期
一致 —— 因为工具 schema 和 prompt 段由 composition 决定，只有真实会话能显示它产出
的 agent 长什么样。

`DEEPSEEK_API_KEY` 与 `DSH_TELEMETRY_DISABLED=1`；用的是已构建的 `bin.js` 而非源码启动。

## 五、卸载

```powershell
Remove-Item "$env:USERPROFILE\.dsh\.agent-presets\verified" -Recurse -Force
```

已运行的会话不受影响（组合在启动时已安装）；未启动的会话将不再看到该项。

## 六、常见问题

**Q：选择器里看不到「核实模式」**
先确认目录名和层级正确（`<dshHome>/.agent-presets/verified/agent.cordis.yml`），
再确认 `preset.yml` 的 YAML 能解析。DSH 会把**无法加载的 preset 连同原因一起列出**
而不是隐藏，所以更可能是路径不对。

**Q：选了但行为没变化**
确认是**新开的会话**。运行中的会话不会重读组合。

**Q：和 `standard` 有什么区别**
只有 persona 多一段。工具集、prompt 段、Skills 全部相同。

**Q：改了文件为什么不生效**
同上 —— 组合在 agent 发布前安装一次。改动只对新会话生效。

**Q：我在别的 DSH 版本上能用吗**
组合文件引用的是发行版包名（如 `@deepseek-ai/dsh-persona`），跨版本可能失配。
若挂载失败会给出上述四类原因之一，据此判断。稳妥做法是把**你自己版本**的
`standard/agent.cordis.yml` 复制一份，只改 `persona.prefix`，而不是直接用本目录的副本。
